# PerfectPixel 商业化设计（付费产品）

> 状态：方向已定，待细化 P1 详细设计后实施。
> 日期：2026-06-23
> 备注：本轮只确定产品形态与建设顺序；功能开发优先，商业化后续再做。

## 1. 产品形态（已决策）

| 维度 | 决策 |
|---|---|
| 交付形态 | 网页（免费试用 / 获客漏斗）+ 桌面付费版（正式使用） |
| 目标市场 | **海外市场**（非国内） |
| AI 费用 | 桌面版 **BYOK**（用户自带 OpenAI/Gemini 等密钥，AI 钱用户自付） |
| 网页试用 | **预制"伪生成"演示**：用户点生成 → 播放加载动画 → 展示事先跑好的高质量结果。零 AI 成本、零滥用风险 |
| 收费模式 | **一次性买断 + 在线激活** |
| 支付/许可 | **LemonSqueezy**（Merchant of Record，自带许可证密钥发放/激活/校验 API） |

### 为什么这些决策
- **BYOK + 买断**：定位最顺。用户已自付 AI 费用，再月付软件租金会觉得别扭、易流失；买断和"只卖软件本身"一致。
- **不自建授权服务器**：LemonSqueezy 自带许可证 API（生成/激活/校验/限制设备数），桌面 app 启动时调它的 validate 接口即可。授权后端从"自研"缩成"调第三方 API"。
- **MoR 解决海外合规**：LemonSqueezy 自动处理各国 VAT/销售税、信用卡/PayPal 收款、退款、防欺诈，无需自己处理税务。
- **防破解到"够用"即可**：桌面软件不可能完美防破解，目标是"让普通用户觉得买比找破解版省事"。在线激活挡掉 90% 随手分享即可，不做加壳/混淆（性价比低）。

## 2. 整体架构

```
① 共享 Go 核心 (internal/sprite + internal/gen) —— 纯逻辑，无桌面依赖，已存在，直接复用
        │
        ├── ② 桌面付费版 (Wails) = 现有 app + 激活/许可校验 + 离线宽限期 + 自动更新
        │
        └── ③ 网页营销/试用站 = 纯前端：落地页/定价/画廊/预制伪生成演示/下载+购买入口
                │
        ④ 支付+许可证 = LemonSqueezy（现成服务，几乎不用自研后端）
```

**真正需要写代码的只有**：② 桌面 app 加激活逻辑（小改动）、③ 网页营销站（新建，纯前端最简单）。
④ 用现成 SaaS，① 已存在。

## 3. 建设顺序（拆成 3 个独立子项目）

| 阶段 | 子项目 | 内容 | 理由 |
|---|---|---|---|
| **P1** | 桌面付费版授权 | 现有 Wails app 加：激活码输入 → 调 LemonSqueezy 校验 → 离线宽限期 → 试用/锁定状态机 | 收钱命门，依赖最少，最先验证"能卖" |
| **P2** | 网页营销/试用站 | 落地页 + 定价 + 画廊 + 预制伪生成演示 + 下载/购买按钮（跳 LemonSqueezy 结账） | 获客漏斗，P1 跑通后导流收款 |
| **P3** | 自动更新 + 打磨 | 桌面自动更新、代码签名（Win/macOS）、崩溃上报等分发体验 | 锦上添花，可晚做，先手动发版也能上线 |

每个子项目独立走「设计 → 计划 → 实现」一轮。**下一步：细化 P1 的详细设计**（激活流程、离线宽限、状态机、防破解程度、代码改动点）。
